# 涉外语言人才动态调度

约定涉外语言人才、活动需求、派遣和反馈的数据结构。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 人才库包含专家、翻译人员和志愿者
- 五所高校参与长期合作
- 青少年志愿服务需要单独管理

## 本地校验

运行项目自带测试即可确认样例资料可读取，且领域标识与版本字段完整。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。

## 调度后台（src/dispatch）

在领域资料之上实现语言服务调度后台，纯标准库、无外部依赖：

- `models.py` / `enums.py` —— 人员侧维护语种方向、能力证明（含有效期）、服务类型、可用时段、所属单位名单、保密级别与历史反馈；活动侧记录场景、地点、时区、敏感程度与候补规则。
- `eligibility.py` —— 唯一的资格判断入口，逐项输出入选理由或拒绝原因；未成年志愿者须同时持有有效监护人与学校授权，且自动避开不适宜内容与高敏感活动。
- `engine.py` —— 派单与留痕：多人同时派单时名额在接受瞬间竞争；每次接受与拒绝都写入只增不改的事件日志；缺席、改期、临时小语种需求都会触发影响重算（先递补候补、再重新派单、找不到人则如实报缺口并给出接力口译建议）。
- `roster.py` —— 最终值守表：每个会议口译、公共讲解、青少年交流岗位都附完整入选理由，导出前独立复核，保证无时间、地点和职责冲突。
- `pool.py` —— 人才库只依据真实服务记录更新（`record_service` 是反馈唯一写入口）；`prune` 定期清出过期证明、过期授权与失效名单，避免越积越多。
- `seed.py` —— 五所合作高校、三类人才（专家/翻译人员/志愿者）与会议口译、公共讲解、青少年交流三场服务样例。
- `demo.py` —— 端到端演示：派单 → 同时派单竞争 → 改期复核 → 临时小语种嘉宾 → 缺席补位 → 服务回填 → 人才库清理 → 输出最终值守表与留痕。

```bash
python -m src.dispatch.demo   # 端到端演示
python -m pytest              # 全部测试（66 项）
```
